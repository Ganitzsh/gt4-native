# Spike R1: the matrix semantics at 0049E480 and 004A5348

Status: answered (ticket A0). Measured 2026-11-07 on `main` 935a477 + local instrumentation (not committed), live
sessions with a release game build (`tools/release_game.py`, native 072a6ab) and a Release host. Questions:
[RISKS.md R1](../RISKS.md).

## Answers

| # | Question | Answer |
|---|---|---|
| 1 | Set 0 object-to-view, set 1 view-to-window in every view? | **Set 0 is object-to-view. Set 1 is view-to-CLIP, not view-to-window.** pgl is GL-like (WIDESCREEN.md:55-60): 004A5348 is MatrixMode, set 0 the modelview, set 1 the projection, a GL perspective (w' = -z, z' = A z + B w). The window mapping is separate: the batch's qwords 197 (scale) and 198 (offset) from the scratchpad viewport (SPR+0xFA0 / +0xFB0, set by pglViewport 0x004A2D60). Seen in the race's main view, mirror, env-map passes, sky, the pre-race screen and the Home garage. Showroom jitter passes and Photo Travel were not measured (R6). |
| 2 | Where each view loads its camera, and at what depth? | Race main view: `render_world` (0033DEA8, entered from RaceNetBattle::virtual_104 0038B520) -> 0033EAB8: MatrixMode(1), LoadIdentity, camera vtable +0x10 (projection); MatrixMode(0), LoadIdentity, camera vtable +0x18 (view). Set 0 there is the course's world-to-view **at the depth set 0's stack has when the view starts**: 0 in the race, 4 on the pre-race screen (its menu code pushed once). Mirror: `render_back_mirror` (00341E50, called from 0033EAB8) loads its own set 0 and set 1. Menus' 3D (the Home garage car): mRenderContextPS2::virtual_64 (00217058) pushes both sets, then the scene (mCarModelPS2 00156950 / 00156AA0, ModelSet2::render 00455708) loads them. |
| 3 | Does set 1 change inside a view? | **Yes, often.** See the projection table below: the course is drawn in two depth ranges (near 0.1 / far 1200 and near 10 / far 120,019 with the same x, y); some objects get a depth bias by a slightly different near plane (0.105, 0.108); the sky its own (near 1, far 1000); the mirror and the env-map passes their own. So the projection must be per instance, not per view. |
| 4 | Course instances: object space = world? | **Yes.** Course instances (CourseData 00396D40) are drawn at set 0's view-start depth with objectToView exactly the view's world-to-view: 102 of a race frame's ~290 instances share it, constant while the camera is still; the camera recovered from it is consistent with the car (below). Sky instances (00396B80) and the env-map backgrounds have objectToView with translation 0 (centred on the eye). |
| 5 | Units, axes | **1 game unit ~ 1 metre.** GS Z from set 1 and the viewport: Z = 8388096.5 + 8388095.5 A - 8388095.5 B / d exactly (d = view distance in game units); for the race view (A = -1.000167, B = -0.2000167) that is Z = 1.678e6 / d - 1392, about 1.678e6 / d at short range (the constant is about 8 % at 100 m and brings Z to 0 at the far plane), against LIGHTING.md's measured 1.6e6 / metres. Independently, the chase camera sits 6.00 units behind and 1.70 above the player car's origin, the bumper camera 0.99 above the ground. Right-handed, +y up, the view looks down -z (GL); camera rotation orthonormal (error 8e-7), det +1. `kGameUnitsPerMetre = 1.0` (within ~5 %; a car-length check against the mesh cache can tighten it in A2). |
| 6 | Does D · set0 · set1 reproduce ModelJob::matrix? | **Exactly.** For every instance, `m = B · A` (0049E480: B = set 0, A = set 1; rows 0-2 times `s->scale` when byte +0xE is set), then rows 0-2 times `cmd->value` when it is not 0 (0049E548), equals the matrix the batch received (qwords 193-196, the setup the next run reads): 270,515 instances over 1,615 frames (race bumper + mirror 71,910, race chase 72,661, menus 125,944), **0 mismatches, largest relative difference 2.3e-7**. |

## Method

Local instrumentation, never committed (`runtime/spike_r1.cpp` and logging in 004A5348, 004A53F8 / 004A5400,
0049D328, `render_world`, `render_back_mirror`, and pgl's batch write / run): `GT4_SPIKE_R1=FILE,FROM,COUNT` logged,
per VBlank in the window, every set switch (both sets, stack tops, caller), push / pop (depth, matrix, caller), each
Cmd 0049D328 drew (A, B, scales, flags, depth, the composite), the batch matrix and viewport qwords written, every
batch run, and snapshots at the views' entry and exit. Callers are the PS2 functions of the host return addresses.
Three headless live sessions from the approved save (Pan Euro race 2, Grand Valley Speedway), each started from
boot with the same pad route: race bumper view with the mirror (VBlanks 4600-4849), race chase view (4850-5109),
menus (Home's garage car and the pre-race screen, 2300-3449). Offline recomposition in numpy.

## Order in a race frame

`render_world` (0033DEA8): the 3 env-map passes (0044E660), then the main view: sky (00396B80), course (00396D40,
near and far passes), cars and their parts (ModelSet2::render 00455708 with 00451AB0, 004524B8, 003E4A28, 003B1070...),
then the mirror (`render_back_mirror` from 0033EAB8, after every main-view instance: 261 then 20 in frame 4725), then
nothing more before `render_world` returns. The HUD's 3D widget is drawn later, outside it. The mirror does not
interleave with the main view, so `ViewEnd` (main) can be sent before the mirror's `ViewBegin`: views need not nest.

Other numbers: a race frame drew 278-324 instances. Set 0 was the current set for every instance (270,515 of
270,515). 0049E480 recomposed for 16 % of the Cmds (the others reuse the previous Cmd's composite, `obj->flag` = 0)
and 0049E548 wrote the batch matrix for 27.5 % (same shape scale as before): the batch's matrix is often older than
the Cmd, so the `Instance` record must carry its own. Byte +0xE (axis scale) on 1.3 % in the race, but 12 % in the menus
(15,064 of 125,944): A2 must not treat it as rare. No skinned Cmd (bits & 0x80) in the race. The race view's
60 x 47.85 degrees give tan(30) / tan(23.93) = 1.30, neither 4:3 (1.333) nor 640 / 448: worth knowing for aspect
and widescreen work.

## Consequences for the contract (CONTRACTS.md a)

1. **`ViewBegin::viewToWindow` is set 1 composed with the viewport, not set 1.** Send `viewToClip` (set 1 when the
   view's camera loads) and the viewport (`viewportScale[4]`, `viewportOffset[4]`, qwords 197 / 198; window =
   offset + scale * clip / w per component, z giving GS Z, w the fog). `fovY`, `aspect`, `nearZ`, `farZ` follow
   from `viewToClip` and can go.
2. **The projection is per instance.** Proposal: a `Projection` record (kind 10: id, view, `viewToClip`, viewport),
   sent when set 1 or the viewport changes inside a view (about 10 a race frame), and `Instance::projection` (the
   id) in place of `Instance::reserved`. The recompose gate (a.7 `matrixChecked`) then reads
   `diag(axisScale * k, 1) * objectToView * projection.viewToClip == ModelJob::matrix` (k = shapeScale or 1), which
   held for every instance measured. B7 needs the per-instance projection for parity (the depth bias and the
   course's two depth ranges change GS Z).
3. **`worldToView` is set 0 at the depth the view starts with**, not at absolute depth 0 (4 in menus). The camera is
   known for race and pre-race views (`kViewCameraKnown`); the R1 fallback is not needed there.
4. **Views: main, mirror, env-map faces (3 a frame, before the main view), sky as part of each view
   (`kInstSky`: objectToView translation 0, from 00396B80), menu 3D (`kViewShowroom` / `kViewOther` from
   mRenderContextPS2::virtual_64).** The HUD widget is a 3D model outside any view (`instancesWithoutView`, 2 a race
   frame): count it, do not gate on it, or open a `kViewOther` around it.
5. **`kGameUnitsPerMetre = 1.0`.**
6. `Instance::matrixSet` was 0 for every instance; keep it as a check.

## Consequences for the tickets

- **A1**: the struct changes above (ViewBegin, Projection, Instance::projection) before the contract lands.
- **A2**: the Instance hook in 0049D328 as planned; A and B are read as 0049E480 picks them (by `s->current`) even when
  0049E480 does not run (the composite then equals the previous Cmd's). The projection id comes from a runtime
  counter bumped by 004A5348 when set 1 is the target of a load, or by comparing set 1 per instance (cheap: 64
  bytes).
- **A3**: the main view's `ViewBegin` after 0033EAB8's camera load (0033EAB8 is decomp source only: a `game_src` copy,
  or a hook in 00456918 / the camera's +0x18 call site), `ViewEnd` before `render_back_mirror`; the mirror's pair in
  00341E50 (game_src). The env-map passes' views around 0044E660 (A6). Menus: mRenderContextPS2::virtual_64
  (00217058).
- **A6 / R6**: showroom jitter passes and Photo Travel still to be measured.
